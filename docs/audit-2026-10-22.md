# XAUCORE: проверка стабильности и производительности, 22.10.2026

Исходная версия: `31ac5fd4371a69aba3ec2597f1d3b5e27273286d`.
Целевой пользовательский сценарий: OnePlus 9R, Chrome, экран 120 Гц, включённая дисперсия.

## Исправления

- Дисперсия переиспользует готовые SVG-фильтры при изменении силы. Сохранены карты преломления, пять спектральных проходов, матрицы цветов и исходные значения scale. Отдельная категория заголовка сохраняет коэффициент 0.6.
- Повторное применение того же стекла сохраняет готовые фильтры и ожидающую подготовку. Выключение стекла, новая геометрия и удаление элемента отменяют устаревшие обработчики.
- График сохраняет анимации активных торговых уровней при количестве более 120; удаляются только устаревшие записи. Исправлена устаревшая формирующаяся свеча при просмотре архивной истории.
- Чтение размеров подпанели перенесено перед записью стилей в кадре без изменения формул геометрии.
- Поздние ответы синхронизации, загрузки истории и отложенные сделки привязаны к исходной сессии. Смена аккаунта отменяет ожидающую работу и защищает namespace локального кэша.
- История зеркального устройства получает новые сделки и после достижения лимита 500 записей; частичное TP1 и финальное закрытие сохраняются отдельно.
- Редактирование отложенного ордера и изменение демонстрационного баланса со второго устройства проходят через ведущую сессию с повторной проверкой ограничений.
- Захват права вести рынок проверяется атомарно в SQL. Одновременные запросы больше не выдают несколько прав управления разным SID и не позволяют старому запросу перезаписать новый lease.
- Добавление в очередь и выдача очереди в heartbeat выполняются атомарно; исправлена потеря одновременно отправленных операций. PUT и live не читают полный state ради проверки lease.
- Вкладки получают отдельные SID; копия вкладки с унаследованным sessionStorage проверяет владение SID через Web Locks перед первым claim.
- Запись архивного чанка и удаление старого поколения истории проверяют lease и текущее поколение в одной транзакции.
- Исправлены гонки регистрации, выдачи и использования кода восстановления, лимита неверных попыток и очистки после ошибки отправки письма. Смена пароля, выдача новой сессии и отзыв старых выполняются одной транзакцией.
- Обработка JSON null больше не роняет auth. Таймер проверки доступа отменяется после завершения запроса. Локальный сервер переживает оборванное тело запроса и некорректный URL.

## Измерения

Последовательные запуски установленного Chrome через Playwright, mobile viewport 412×900, DPR 3, работающий симулятор, изолированные API-заглушки. В обоих запусках одинаковый начальный seed. Это настольная среда с дисплеем 60 Гц; её кадровые интервалы не подтверждают 120 FPS на телефоне.

Проход силы дисперсии 0→100, по 300 мс на значение, после одинаковых навигации, панорамирования и прокрутки:

| Показатель | До | После |
|---|---:|---:|
| SVG-фильтры перед проходом | 26 | 26 |
| SVG-фильтры после прохода | 326 | 26 |
| Displacement nodes после прохода | 1550 | 50 |
| Узлы внутри SVG defs после прохода | 5312 | 212 |
| ScriptDuration за проход, с | 0.4610 | 0.3623 |
| RecalcStyleDuration за проход, с | 0.3719 | 0.2399 |

Количество объектов воспроизводимо; значения времени зависят от нагрузки и не являются обещанием ускорения на тот же процент на телефоне. В проверенных сценариях с включённой дисперсией p95 интервала rAF оставался около 16.8–17.0 мс в этой 60-Гц среде. Наблюдатель longtask не зарегистрировал задач длиннее 50 мс. Полный GPU frame time на OnePlus не измерен.

12 120 комбинаций силы, преломления, категории элемента и спектрального прохода дали те же строки scale, что исходная формула. Основная нижняя плашка, форма капли, темы, длительности появления/затухания и пять цветовых проходов не перерабатывались.

## Границы проверки

- Фактические стабильные 120 FPS требуют замера на физическом OnePlus 9R в Chrome: для этого доступно менее 8.34 мс на кадр. Программного общего ограничения 60 FPS в коде не обнаружено. Нагрузка GPU, частота, выдаваемая браузеру системой, и нагрев устройства здесь не проверены.
- Существующий протокол удалённых операций выдаёт очередь с очисткой. Потеря самого ответа heartbeat после успешной транзакции всё ещё может потерять доставку операции. Для гарантированной доставки требуется отдельный протокол подтверждения и идемпотентного повторения; текущие исправления закрывают воспроизведённые гонки одновременных запросов.
- Закрытый брокерский кошелёк (`WALLET_SOON=true`) остаётся незавершённой функцией; его межустройственные операции не включались.
- Удерживаемый Web Lock освобождается при уничтожении документа и может ограничивать BFCache. При отсутствии Web Locks используется уникальный SID документа; если сохранение/release при перезагрузке не дошли, действует прежнее истечение lease через 20 секунд. [Web Locks](https://www.w3.org/TR/web-locks/), [копирование sessionStorage](https://storage.spec.whatwg.org/#legacy-clone-a-traversable-storage-shed).
- Политики rate limit для login/register/owner и существующие ответы при повторном запросе reset-кода не менялись. Локальные тесты не моделируют все задержки и отказы производственного Turso, почты и сети.

Проверка охватывает основные подсистемы и воспроизведённые ошибки; утверждение «в проекте больше нет ни одного бага» из этих результатов не следует.
