# XAUCORE — DEMO / SYNTHETIC XAUUSD trading simulator

`DEMO • SYNTHETIC DATA` — **no real quotes, no broker, no real accounts, no real trades.**
Every price, candle, spread, commission, swap, margin figure and news event is generated by
the app itself. Nothing connects to a real market.

Deployable web app with per‑user cloud save: the whole simulator **freezes when you leave the
site and resumes exactly where it stopped** — 5 minutes, 5 hours or 5 days later, from any
device you sign in on.

---

## 1. Architecture

| Layer | Choice | Why |
|---|---|---|
| **Frontend** | Single self‑contained `public/index.html` (vanilla JS, canvas chart). Kept from the existing project — not rewritten. | The whole simulator is one `S` state object; that object *is* the save. |
| **Backend** | `server.js` — **zero npm dependencies**: `node:http` + `node:sqlite` + `node:crypto` (Node ≥ 22.5). | Nothing to `npm install` → nothing to break on deploy. Serves the static app **and** the API. |
| **Database** | SQLite file (`DB_PATH`, default `./data/xaucore.db`), WAL mode. Tables: `users`, `sessions`, `states`. | One file, on a mounted volume in production. Trivial backups. |
| **Auth** | Email + password (`scrypt` hash) **or** anonymous *guest*. Opaque random session tokens (revocable), 1‑year TTL. A guest can later *upgrade* to a real account and keep all progress. | Simple, no JWT library, works across devices. |
| **Sync** | `localStorage` = fast local cache / offline fallback. Server = source of truth. State is pushed (debounced 3.5 s) on every change, and force‑pushed on tab‑hide / page‑unload (`sendBeacon`). | Multi‑device, offline‑tolerant. |

### The "freeze while away" guarantee

* The price engine never derives time from an absolute `Date.now()` endpoint. Day progress and
  market‑regime age are **accumulated** (`day.elapsedMs`, `regime.ageMs`) from *active* wall‑time
  only, and each frame's delta is **capped to one frame** — a gap of minutes/hours/days counts
  as a single 60 ms step, never a leap.
* `visibilitychange` **stops every timer** while the tab is hidden. Nothing advances.
* On return the exact saved state is restored (verified byte‑for‑byte) and the simulation
  continues from that point the moment you interact with it.

### API

```
POST /api/auth/register   {email,password}      -> {token,id,email,isGuest}
POST /api/auth/login      {email,password}       -> {token,id,email,isGuest}
POST /api/auth/guest                             -> {token,id,email:null,isGuest:true}
POST /api/auth/upgrade    {email,password}  (auth, guest only)  -> {email,isGuest:false}
POST /api/auth/logout     (auth)
GET  /api/me              (auth)                 -> {id,email,isGuest}
GET  /api/state           (auth)                 -> {state,updatedAt}
PUT  /api/state           {state}  (auth)        -> {updatedAt}         also accepts ?token= (unload beacon)
GET  /api/health                                 -> {ok:true}
```

Each account's state is cached in `localStorage` under a **per-user key** (`xc_state_<id>`),
so two accounts used in the same browser never see each other's local copy — the server
state always wins on sign-in. The state blob (mostly chart candles) exceeds `sendBeacon`'s
64 KB limit, so the on-exit save uses `visibilitychange`→async push first, then a
synchronous same-origin `XHR` on `pagehide` as the guaranteed fallback.

## 2. Run locally

Requires **Node 22.5+** (uses the built‑in `node:sqlite`). Node 24 recommended.

```bash
node server.js
```

Open <http://localhost:8777>. That's it — no build step, no dependencies.

Optional env vars: `PORT` (default `8777`), `HOST` (default `0.0.0.0`), `DB_PATH`
(default `./data/xaucore.db`).

Debug: append `?boot=paused` to the URL to restore the saved state **without** advancing the
simulation (useful for inspecting the exact resume point).

## 3. Deploy

The repo ships a `Dockerfile` (no `npm install` — image just copies the files), plus
`fly.toml` and `render.yaml`. The **one requirement** in production is a **persistent volume
mounted at `/data`** so the SQLite database survives restarts and redeploys.

### Docker (any host / VPS)

```bash
docker build -t xaucore .
docker run -d --name xaucore -p 80:8777 -v xaucore_data:/data --restart unless-stopped xaucore
```

Put Caddy / Nginx / a load balancer in front for HTTPS, or run it behind the platform's own TLS.

### fly.io (has free volumes)

```bash
fly launch --no-deploy
fly volumes create xaucore_data --size 1 --region <region>
fly deploy
```

### Render.com

Dashboard → **New → Blueprint** → pick the repo (`render.yaml` is detected). Add the **Disk**
(1 GB at `/data`) — Disks need a paid instance type; on the free plan the DB is wiped on each
redeploy.

## 4. Custom domain `xaucore.io`

1. Deploy first and note the platform hostname (e.g. `xaucore.fly.dev` / `xaucore.onrender.com`).
2. In the platform, **add the custom domains** `xaucore.io` and `www.xaucore.io`.
3. At your DNS provider (where `xaucore.io` is registered) create the records the platform shows:
   * `xaucore.io` → `A` / `AAAA` records (Fly) **or** an `ALIAS`/`ANAME` at the apex (Render).
   * `www.xaucore.io` → `CNAME` to the platform hostname.
4. Wait for DNS to propagate; the platform issues the TLS certificate automatically.
   * Fly: `fly certs add xaucore.io && fly certs add www.xaucore.io`
   * Render: certificates are automatic once the DNS records verify.

No app config change is needed — the server binds `0.0.0.0:$PORT` and serves any Host.

## 5. What is saved (per user, in the DB)

Current XAUUSD price · Bid / Ask / Spread · Balance · Equity · Margin · Free Margin · Margin Level ·
all open positions (volume, entry, SL, TP, swap, commission) · Floating P/L · full trade history +
statistics · current simulated **Day** number · **time inside the day** · complete Price‑Engine
state (velocity, EMAs, volatility‑cluster) · current **Market Regime** and its age · every
Simulator Setting · Manual Market Control settings · the candle history for every timeframe.

Re‑opening the site (same browser or a different device signed into the same account) restores
**all** of it exactly and the simulation carries on from there. Nothing moved while you were gone.

## 6. Verified test scenario

1. Open the site → register / login (or play as guest).
2. Trade — open a few positions, set SL/TP.
3. Note price, balance, positions, day, time.
4. Fully close the site (or clear the browser).
5. Re‑open → auto‑restore (token) or sign in again.
6. **Exact match** — price / Bid / Ask / balance / equity / positions / SL / TP / day / time /
   regime / candle count restored byte‑for‑byte.
7. Continue trading — simulation resumes from that point.
8. While away (loop stopped): price, day time, sim clock, candles — **completely frozen**;
   a simulated 5‑hour gap advances the day by ~60 ms, never a leap; no extra day rollover.
9. Multi‑device: signing into the same account from a fresh browser restores the same state.
